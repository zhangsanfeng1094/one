  # One Config Studio：统一配置管理与生效诊断方案

  ## 1. 定位与交付原则

  定位为 One 内置的本地配置控制台：统一发现配置、解释生效来源、提供强类型编辑和可靠保存。

  采用已确认的方向：

  - 完整配置目录，分期可编辑：先覆盖所有配置的来源与状态，再逐步增加专用编辑体验。
  - 沿用运行时语义：不为界面统一而新增项目覆盖规则。
  - 首版优先完成配置闭环：读取 → 编辑 → 校验 → Diff → 保存 → 明确生效时机。

  “零外部依赖”指用户运行已发布二进制不需要 Node.js；前端开发和构建仍需要工具链。

  ## 2. 配置模型与信息架构

  核心调整：作用域是编辑目标，生效配置是解析结果，两者分开呈现。

  顶部选择当前项目与编辑作用域；模块内提供“当前层配置”和“最终生效配置”。后者只读，并显示来源、覆盖关系及启动参数／环境变量的影响。预览基于 Studio 启
  动上下文，不宣称代表其他运行中会话。

  落实以下语义：

  - settings.json 目前是全局配置，项目视图显示“全局专属”，不提供虚假的项目覆盖按钮。
  - MCP 同名服务按现有规则整条替换；创建项目覆盖时复制完整条目，并解释删除覆盖后会重新使用上层配置。
  - 项目来源可能包含祖先目录；界面显示真实路径，不简化成只有两个文件。
  - 内置和第三方资源默认只读，通过运行时已支持的方式创建自定义配置。
  - 会话记录、缓存、日志和记忆正文属于运行数据，不纳入“配置编辑”。

  ## 3. 技术架构与编辑流程

  复用现有 one-web 和 React 前端，增加 /config 页面；新增 one config 启动入口。 独立启动配置中心不要求模型或认证已配置成功。

  后端分成三层：

  - 模块适配器：复用各模块真实的解析、校验和来源解析逻辑，避免 Studio 维护第二套配置规则。
  - 配置服务：统一管理文档、草稿校验、差异、版本冲突和保存。
  - Web API：提供配置目录、文档读取、校验、变更预览、提交、备份恢复及诊断任务接口。

  每个模块声明支持的作用域、格式、敏感字段、编辑能力、覆盖规则和生效时机。API 使用受控资源 ID 定位文档，不接受任意文件路径。

  编辑采用“一份文本草稿，两个视图”：

  - 表单修改更新草稿；源码解析成功后刷新表单。
  - 源码无效时保留用户输入，展示错误位置，暂停表单编辑。
  - Schema 辅助生成基础控件；模型、权限、MCP 等复杂模块使用专用组件。
  - Serde 负责类型解析；额外执行范围、字段组合和跨资源引用校验。
  - 保留未知字段；不因表单保存而静默删除未来版本字段。TOML 编辑保留注释。
  - 读取损坏配置时展示原文与诊断，不调用会自动迁移或回退默认值的加载路径掩盖错误。

  接口至少统一返回：文档版本、来源、支持能力、字段诊断和生效说明。运行时与 Studio 的校验规则以共享代码为准。

  ## 4. 可靠保存、本地安全与诊断

  保存以单文档为事务边界，首版不提供跨文件“一键全部保存”。

  保存流程固定为：

  1. 校验草稿并生成脱敏 Diff，显示目标文件和影响。
  2. 用户确认后，重新检查文件内容版本；外部修改导致冲突时停止覆盖。
  3. 备份旧内容，写入同目录临时文件，同步后原子替换。
  4. 返回新版本、备份记录与生效说明。

  补充约束：

  - Studio 写入串行化；现有配置写入入口逐步接入共享写入服务。内容版本检查防止常见并发覆盖，但不承诺对不遵守锁的外部编辑器提供绝对隔离。
  - 备份放在模块加载器不会扫描的位置，按文档保留最近 10 版；恢复也通过校验与版本检查。
  - 凭据默认脱敏；“保持、替换、清除”是明确操作，掩码不能写回真实配置。需要查看完整源码时显式解锁，敏感内容不进入浏览器持久存储或日志。
  - 仅监听回环地址，启动时生成临时访问凭证，并校验 Host、Origin；配置 API 与静态资源同源。
  - 首版默认“新会话生效”，不自动修改现有会话或重启 MCP。

  诊断放在后续阶段，采用可取消的后台任务：

  - Provider 分开显示网络可达、认证结果、模型列表获取和实际推理测试；不使用统一 HTTP HEAD 判定成功。
  - MCP 由用户主动触发启动，执行握手及工具枚举，设置超时并清理子进程；不自动调用工具。
  - 诊断可使用未保存草稿，结果绑定草稿版本；保存不以联网成功为前提。

  必须覆盖的测试：

  - 全局、项目、祖先目录、内置资源及启动覆盖的解析结果与运行时一致。
  - MCP 整条覆盖、删除覆盖后恢复继承。
  - 非法语法、未知字段、缺失引用及无配置状态。
  - 表单／源码往返不丢字段；敏感字段保持与清除语义正确。
  - 多标签页、外部编辑、备份失败、写入失败及恢复。
  - 未授权访问、跨源请求、路径越界和符号链接越界。
  - 前端构建后静态资源完整嵌入；发布二进制能独立启动配置页面。

  首版成功标准是：用户能够准确判断“改的是哪里、最终用的是什么、保存是否可靠、何时生效”。
